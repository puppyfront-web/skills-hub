# JD Match Scoring · 六维匹配度评分细则

对每条候选岗位，按六维模型打分。每个维度 0–5 分，加权汇总后映射到 A/B/C/D 档位。

---

## 1. 评分维度与权重

| 维度 | 权重 | 评什么 |
|---|---|---|
| 技能匹配 | 30% | JD 必备技能 vs 用户简历技能 |
| 经验年限 | 20% | JD 要求年限 vs 用户实际年限 |
| 行业/领域 | 15% | 行业背景匹配度 |
| 地域/远程 | 15% | 地点或远程政策是否符合用户要求 |
| 薪资匹配 | 10% | JD 薪资 vs 用户期望 |
| 平台可信度 | 10% | 招聘方资质、JD 完整度 |

---

## 2. 各维度评分标准

### 2.1 技能匹配（30%）

**核心问题**：用户已掌握的技能 vs JD 必备技能。

| 分 | 标准 |
|---|---|
| 5 | 全部必备技能都掌握，且多数加分技能也有 |
| 4 | 必备技能满足 ≥ 80%，加分技能部分满足 |
| 3 | 必备技能满足 60–80% |
| 2 | 必备技能满足 40–60%（可补学习但门槛高） |
| 1 | 必备技能满足 20–40%（差距大） |
| 0 | 必备技能几乎都不沾边 |

**判定要点**：
- 必备技能 = JD 里「要求」「必须」「熟练」字样的技能；加分技能 = 「优先」「加分」「nice to have」。
- 同义技能可合并（React/React.js、Python/Py、K8s/Kubernetes）。
- 「X 年经验」也算技能维度的一部分（如「3 年 Python」算技能熟练度）。

### 2.2 经验年限（20%）

| 分 | 标准 |
|---|---|
| 5 | 实际年限 ≥ JD 要求 + 2 年 |
| 4 | 实际年限 = JD 要求 ± 1 年 |
| 3 | 实际年限 = JD 要求 − 2 年（临界） |
| 2 | 差距 2–4 年 |
| 1 | 差距 > 4 年（如要求 5 年，实际 < 1 年） |
| 0 | 完全不匹配（应届生投资深岗） |

**特殊情况**：JD 没写年限要求 → 默认 4 分（不卡）。

### 2.3 行业/领域（15%）

| 分 | 标准 |
|---|---|
| 5 | 用户直接从事过 JD 所在行业（同行业同细分） |
| 4 | 相关行业（如电商→零售） |
| 3 | 跨但相近（如 ToC→ToB，技能可迁移） |
| 2 | 跨行业但通用技能为主 |
| 1 | 跨行业且高度领域专精（如医疗算法岗 vs 通用开发） |
| 0 | 完全不相关 |

**示例**：用户是电商后端，投金融后端 → 3 分（技能可迁移，行业不同）；投医疗影像算法岗 → 1 分。

### 2.4 地域/远程（15%）

| 分 | 标准 |
|---|---|
| 5 | 地点完全匹配用户要求（同城市），或 JD 明确支持纯远程且用户要 remote |
| 4 | 同城不同区，或通勤可接受 |
| 3 | 跨城但用户已表示可接受；或「混合办公」（部分远程） |
| 2 | 跨省/跨国，用户需搬迁 |
| 1 | 完全不在用户目标地域内 |
| 0 | 强制坐班且地点不可接受 |

**关键判定**：用户的「地域/远程」要求在 Step 1 已澄清，评分时严格对照。

### 2.5 薪资匹配（10%）

| 分 | 标准 |
|---|---|
| 5 | JD 薪资 ≥ 用户期望上限 |
| 4 | JD 薪资在用户期望区间内 |
| 3 | JD 薪资略低于期望（差 10–20%） |
| 2 | 明显低于期望 |
| 1 | 远低于期望 |
| 0 | 完全不可接受 |

**特殊情况**：JD 没写薪资（小红书常见）→ 默认 3 分，并在档案卡标 `[薪资未公开]`。

### 2.6 平台可信度（10%）

评估招聘方资质与 JD 真实性。

| 分 | 标准 |
|---|---|
| 5 | 知名公司官方招聘 + JD 详细完整（V2EX 大厂认证号 / LinkedIn 官方公司页） |
| 4 | 中小公司创始人/HR 直接发帖，JD 完整 |
| 3 | 普通招聘帖，JD 基本完整 |
| 2 | JD 拼凑、信息不全、疑似中介/培训 |
| 1 | 疑似 spam、无公司信息、要求先交费/培训 |
| 0 | 明显诈骗红旗（高薪低门槛、要求押金、私人微信加好友等） |

**红旗清单**（任一命中直接打 0–1 分）：
- 「零基础月入过万」「不需要经验」+ 高薪
- 要求交培训费、押金、试岗费
- 公司信息完全不可查（搜不到官网、无 LinkedIn 页）
- V2EX 帖子被 marked/deleted
- 小红书笔记评论区一片「已私信」刷屏（疑似批量引流）

## 3. 加权汇总与档位映射

**加权公式**：

```
总分 = 技能×0.30 + 年限×0.20 + 行业×0.15 + 地域×0.15 + 薪资×0.10 + 可信度×0.10
```

总分范围 0–5。

**档位映射**：

| 档位 | 总分 | 含义 | 默认动作 |
|---|---|---|---|
| **A 强匹配** | ≥ 4.0 | 强烈推荐投 | 生成定制简历 + 推荐投 |
| **B 可投** | 3.0–3.9 | 值得一试 | 生成定制简历 + 备投 |
| **C 备选** | 2.0–2.9 | 备用，不优先 | 仅归档，不生成简历 |
| **D 不投** | < 2.0 | 不建议 | 丢弃 |

**硬否决规则**（即使总分高也降级）：
- 平台可信度 = 0 或 1 → 强制降到 D（防诈骗优先）。
- 地域/远程 = 0 → 强制降到 D（用户不会去）。
- 技能匹配 ≤ 1 → 强制降到 D（差距过大，投了也浪费）。

---

## 4. 评分输出格式

每个候选岗位的评分块（嵌入档案卡第 3 节）：

```markdown
## 3. 匹配度（{A/B/C/D} + 总分 {x.x}/5）
| 维度 | 得分 | 加权 | 依据 |
|---|---|---|---|
| 技能匹配 | x/5 | x.xx | JD 要 Python+Django；简历有 3 年 Django |
| 经验年限 | x/5 | x.xx | 要求 5 年，实际 4 年（−1） |
| 行业/领域 | x/5 | x.xx | 同为电商 SaaS |
| 地域/远程 | x/5 | x.xx | 深圳，用户要求深圳 |
| 薪资匹配 | x/5 | x.xx | 20-30k，用户期望 25-35k |
| 平台可信度 | x/5 | x.xx | V2EX 官方账号，JD 详细 |
```

**依据行必须具体**，不允许「经验匹配」「技能相近」这种空泛描述。

## 5. 评分示例（参考）

**示例 1：强匹配 A 档**

用户：4 年 Python 后端，电商行业，深圳，期望 25-35k，要远程
岗位：V2EX `[远程 30-50k] Python 后端（电商 SaaS）`，要求 5 年 Python + Django

| 维度 | 得分 | 依据 |
|---|---|---|
| 技能匹配 | 5/5 | Python+Django 全满足，加分 |
| 经验年限 | 4/5 | 要求 5 年，实际 4 年 |
| 行业/领域 | 5/5 | 同电商 SaaS |
| 地域/远程 | 5/5 | 完全远程 |
| 薪资匹配 | 5/5 | 30-50k 高于期望 |
| 平台可信度 | 4/5 | V2EX 详细 JD |

加权：5×.3 + 4×.2 + 5×.15 + 5×.15 + 5×.1 + 4×.1 = 1.5+.8+.75+.75+.5+.4 = **4.70 → A 强匹配**

**示例 2：可投 B 档（硬否决未触发但分中等）**

用户：3 年 Java 后端
岗位：LinkedIn Python 后端 4 年，金融行业，北京，30k

| 维度 | 得分 | 依据 |
|---|---|---|
| 技能匹配 | 2/5 | Java→Python 跨栈，Java 经验可迁移但 Python 实战不足 |
| 经验年限 | 4/5 | 4 年要求，实际 3 年 |
| 行业/领域 | 2/5 | Java 电商→Python 金融，双重跨 |
| 地域/远程 | 5/5 | 假设用户在北京 |
| 薪资匹配 | 4/5 | 30k 在期望内 |
| 平台可信度 | 5/5 | LinkedIn 大厂官方 |

加权：2×.3 + 4×.2 + 2×.15 + 5×.15 + 4×.1 + 5×.1 = .6+.8+.3+.75+.4+.5 = **3.35 → B 可投**

档案卡第 2 节「一句话结论」应写：「Python 实战不足是硬伤，但金融 + 大厂 + 薪资匹配，值得用定制简历突出可迁移能力投一次。」

## 6. 常见误用

- ❌ **只看技能维度**：6 个维度都要评，地域、可信度常被忽视但很重要。
- ❌ **依据空泛**：「匹配」「相关」不算依据，要写具体年限/技能/数字。
- ❌ **降级忘加**：硬否决规则一定要检查，可信度 0–1 必须降到 D。
- ❌ **薪资没写就打 0**：JD 没薪资很常见，默认 3 分并标注，不要直接打 0。
