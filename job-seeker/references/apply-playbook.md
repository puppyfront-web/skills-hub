# Apply Playbook · 投递 SOP

投递阶段（Step 6）的标准操作流程。三档自动化 + 节流 + 降级 + 归档。

---

## 1. 三档自动化

| 档位 | 适用平台 | 行为 | 用户参与 |
|---|---|---|---|
| **半自动（默认）** | 全部 | 生成「岗位 + 定制简历 + 投递链接/邮件草稿」 | 用户确认后**手动点投/复制粘贴** |
| **全自动** | 仅 LinkedIn（需 Phase 3 模块） | 调 `linkedin-apply` npm 模块 | 投前确认，投中无需操作 |
| **邮件直投** | V2EX 外链邮箱 / 远程社区 | 生成邮件草稿 | 用户确认后通过邮件客户端发送 |

**默认选择**：半自动。除非用户明确说「自动投 LinkedIn」并已配置好 Phase 3 模块。

---

## 2. 投递前准备（必做）

每次投递前，**无论哪档自动化**，都必须先完成：

1. **确认 Step 4 评分**：岗位必须是 A 或 B 档。C/D 档不投。
2. **确认 Step 5 简历**：定制版 PDF 已生成并落盘到 `jobs/resumes/`。
3. **确认就业类型匹配**：用户要「远程」，岗位 JD 必须明确支持远程。歧义时停下问用户。
4. **更新 INDEX 行**：在 `jobs/INDEX.md` 找到该岗位行（或追加），把状态改成 `🟡 已投递`，填投递日期、简历版本。
5. **告知用户风险**（仅 LinkedIn 全自动档）：明确说「自动投递违反 LinkedIn 协议，有封号风险，确认继续？」

## 3. 半自动投递 SOP

### 3.1 V2EX 半自动

V2EX 帖子大多给邮箱或要求跟帖联系，少数有外链投递系统。

**输出投递包**（一份 Markdown）：

```markdown
# 📤 投递包 · {公司简称}-{岗位}

## 岗位信息
- 来源：{V2EX URL}
- 公司：{公司}
- 岗位：{岗位}
- 联系方式（从 JD 提取）：{邮箱 / 微信 / 跟帖}

## 定制简历
- 路径：`jobs/resumes/resume-<...>.pdf`

## 邮件草稿（若 JD 留邮箱）
**主题**：应聘 {岗位} - {用户姓名} - {年限}年经验
**正文**：
{根据 JD 定制的求职信，3 段以内：1) 申请什么岗 2) 为什么匹配 3) 附件简历}

附件：resume-<...>.pdf

## 跟帖文案（若 JD 要求跟帖）
{一段简短跟帖，5-50 字，表达意向 + 邮箱}
```

**用户操作**：复制邮件草稿 → 用邮件客户端发送；或回 V2EX 帖子跟帖。本 skill **不代发邮件**（V2EX 邮件直投阶段保守，避免误发）。

### 3.2 LinkedIn 半自动

**输出投递包**：

```markdown
# 📤 投递包 · {公司}-{岗位}

## 岗位信息
- 来源：{LinkedIn URL}
- Easy Apply：{是/否}
- 招聘官（若搜到）：{姓名 + LinkedIn 主页}

## 定制简历
- 路径：`jobs/resumes/resume-<...>.pdf`

## 操作步骤
1. 打开 {URL}
2. 点 Easy Apply（或「上传简历申请」）
3. 上传 `resume-<...>.pdf`
4. （可选）填表单字段：{本 skill 给出每个字段建议填什么}
5. 提交

## 给招聘官的 InMail 草稿（可选，若搜到 HR）
{一段 200 字以内的消息：表达意向 + 一句话匹配理由 + 简历附件}
```

**用户操作**：手动打开链接、上传简历、提交。

### 3.3 小红书半自动

小红书招聘号通常要私信/加微信。

**输出投递包**：

```markdown
# 📤 投递包 · {公司}-{岗位}

## 来源笔记
- URL：{小红书笔记 URL}
- 招聘方：{发布者}
- 联系方式：{评论区线索 / 「私信」 / 微信号}

## 私信草稿
{一段 100 字以内的私信：表达意向 + 一句话背景 + 询问完整 JD 和投递方式}

## 备注
⚠️ 小红书招聘信息常不全，建议先私信确认：
- 完整 JD
- 公司全名（便于背调）
- 是否真实招聘（避免培训/中介）
```

**用户操作**：复制私信 → 在小红书 App 发送。

## 4. LinkedIn 全自动投递（Phase 3 模块，可选）

**前置条件**：
- Phase 3 的 `linkedin-apply` npm 模块已安装在 `/Users/tutu/Documents/linkedin-apply/`
- 首次登录已完成：`node dist/cli.js linkedin login --account main`
- 登录态有效：`node dist/cli.js linkedin check --account main` 返回 valid

**单条投递**：

```bash
node /Users/tutu/Documents/linkedin-apply/dist/cli.js linkedin apply \
    --account main \
    --job-url "{LinkedIn JD URL}" \
    --resume "/abs/path/resume-<...>.pdf"
```

**批量投递（节流）**：

```bash
# 准备 jobs.json（A/B 档岗位 + 对应简历路径）
cat > /tmp/apply-jobs.json <<EOF
[
  {"url": "https://linkedin.com/jobs/view/XXX", "resume": "/abs/path/resume-a.pdf"},
  {"url": "https://linkedin.com/jobs/view/YYY", "resume": "/abs/path/resume-b.pdf"}
]
EOF

node /Users/tutu/Documents/linkedin-apply/dist/cli.js linkedin apply-batch \
    --account main \
    --jobs /tmp/apply-jobs.json \
    --max 5 \
    --interval-min 60 \
    --interval-max 180
```

**8 阶段进度协议**（linkedin-apply 模块输出，本 skill 解析后转告用户）：

```
✅ [1/8] INIT - 初始化
✅ [2/8] COOKIE_CHECK - 登录态有效
⏳ [3/8] COOKIE_REFRESH - 刷新登录态（仅在 check 失败时）
✅ [4/8] JOB_OPEN - 打开岗位页
✅ [5/8] EASY_APPLY_OPEN - 启动 Easy Apply
⏳ [6/8] FORM_FILL - 填写表单
⏳ [7/8] RESUME_UPLOAD - 上传简历
✅ [8/8] SUBMIT - 提交完成
```

---

## 5. 节流参数（强制）

LinkedIn 风控敏感，**必须节流**：

| 限制 | 值 |
|---|---|
| 单次 `apply-batch` 上限 | **5 个** |
| 投递间隔 | 随机 **60–180 秒** |
| 单日累计上限 | **25 个**（超过自动停止） |
| 单周累计上限 | **80 个** |
| 连续失败上限 | **3 次**（连续失败后停止，提示用户） |

**节流日志**：批量投递时输出累计计数，超过日上限立即停止：

```
[批量投递] 今日已投 22/25，本次再投 3 个后达到日上限，停止
```

**日累计持久化**：linkedin-apply 模块维护 `~/.linkedin-apply/state/daily-counter-<YYYYMMDD>.json`，跨会话累计。

## 6. 降级与失败处理

### 6.1 登录态失效

**检测**：linkedin-apply 模块的 COOKIE_CHECK 阶段失败（被重定向到登录页）。

**处理**：
- 半自动：提示用户「LinkedIn 登录已过期，请手动登录或重新跑 `linkedin login`」
- 全自动：尝试自动 fallback 到 `login` 流程（弹浏览器等用户扫码），失败则停止本轮

### 6.2 人机验证（CAPTCHA / Auth Wall）

**检测**：linkedin-apply 收集页面 blocking 文本含 `auth_wall` / `challenge` / `security verification`。

**处理**：
- 立即停止当前操作
- 抛诊断错误：`检测到 LinkedIn 人机验证。建议设置 LINKEDIN_APPLY_HEADLESS=0 重新跑，或手动投递本岗位。`
- **不尝试绕过验证码**（违反 SKILL.md 硬约束 + 平台协议）

### 6.3 Easy Apply 表单字段缺失

**检测**：表单要求字段（如「合法工作身份」「是否需要赞助签证」「几年相关经验」）本 skill 没数据。

**处理**：
- 暂停当前投递
- 收集缺失字段清单，提示用户：
  ```
  Easy Apply 表单需要以下字段，请提供：
  1. 合法工作身份（是/否）
  2. 是否需要签证赞助（是/否）
  3. 期望薪资（USD）
  ```
- 用户回答后填入，继续

### 6.4 投递被拒（HTTP 4xx / 平台报错）

**处理**：记录失败到 INDEX 该行的备注列，跳过下一条，不阻塞批量。

## 7. 投递后归档

每次投递完成（无论成功失败），必须更新 `jobs/INDEX.md`：

| 场景 | INDEX 行变化 |
|---|---|
| 投递成功 | 状态 → `🟡 已投递`，填投递日期 + 简历版本 |
| 投递失败（可重试） | 状态保持 `📋 待投`，备注列写失败原因 |
| 投递失败（永久，如岗位下线） | 状态 → `🔴 拒绝`，备注「岗位已下线」 |
| 全自动批量 | 每条按上述规则分别更新 |

**简历版本列**填 `jobs/resumes/` 下的相对路径（如 `resume-acme-be-20260726.pdf`）。

## 8. 今日报告（Step 6 末尾必产）

每次运行结束，输出一份「今日报告」（基于 INDEX 自动汇总）：

```markdown
# 📊 今日求职报告 · {YYYY-MM-DD}

## 概览
- 拓岗数：{N}（V2EX {n1} / LinkedIn {n2} / 小红书 {n3}）
- A 档：{n} · B 档：{n} · C 档备选：{n} · D 档丢弃：{n}
- 今日投递：{n} 条（半自动 {n1} / 全自动 {n2} / 邮件 {n3}）
- 累计待跟进：{n} 条（已投但未回复）

## 今日新岗位（A 档，{n} 条）
| 公司 | 岗位 | 平台 | 一句话 |
|---|---|---|---|
| ... | ... | ... | ... |

## 今日投递（{n} 条）
| 公司 | 岗位 | 平台 | 方式 | 简历版本 |
|---|---|---|---|---|
| ... | ... | ... | 半自动 | resume-<...>.pdf |

## 待跟进（{n} 条，超 {N} 天未回复）
| 公司 | 岗位 | 投递日期 | 天数 | 建议动作 |
|---|---|---|---|---|
| ... | ... | 2026-07-10 | 16 | ⚪ 转沉默 / 跟进一次 |

## 下次建议
- LinkedIn 今日已投 {n}/25，剩余配额 {n}
- {N} 条 C 档备选可降级试投
- {N} 条已投超 14 天，建议转 ⚪ 或跟进
```

**报告落盘**：`jobs/reports/report-<YYYYMMDD>.md`。

**自动转状态规则**：
- 已投递超 14 天无回复 → 自动 `⚪ 沉默`
- 收到回复但未推进 → `🟢 收到回复`
- 进入面试 → `🔵 面试中`（需用户告知）
- 明确拒绝 → `🔴 拒绝`（需用户告知）

## 9. 常见误用

- ❌ **跳过节流**：哪怕用户催「快投」，LinkedIn 节流不可破。
- ❌ **全自动未确认**：全自动投递前必须显式告知风险并等用户确认。
- ❌ **投完不归档**：INDEX 必须同步更新，否则今日报告数据错误。
- ❌ **用同份简历投多家**：违反 SKILL.md 硬约束第 3 条（不批量同质化投递）。
