# 小学数学作业批改助手

## 新手介绍与使用指引

面向**第一次使用**本技能的老师，Agent **优先**在开场用简短、口语化的中文做下面几件事（不要一上来就进命令或技术词）：说清「能帮你做什么」→「你要准备什么」→「你大概会经历哪几步」。

### 这技能是干什么的（给老师听的大白话）

- 你把**小学数学作业**拍照发过来，我帮你**认题、批改、指错、讲解**，还能针对错题**出同类练习**。
- 批改结果会告诉你：每道题对不对、错在哪、为什么错、正确解法是什么。
- 学生的错题会**自动记下来**，下次你说「看看小明的学情」，我给你汇总他哪里薄弱。

### 使用前要准备什么

- **照片**：手机拍清楚，尽量正着拍、不糊、不裁断题目。一张图多道题也行。
- **学生名字**（可选）：告诉我是谁的作业，我好记到他的学情里。不说也能批改，只是不记学情。

### 老师会经历的几步

1. **发图** → 我认题、批改，告诉你对了几道、错了几道
2. **看解析** → 错题我会给点评和讲解，你直接拿去讲评
3. **要练习** → 你说「第3题出两道同类题」，我针对错题出变式练习
4. **查学情** → 你说「看看小明的学情」，我给你汇总

### 当用户说「不会用 / 怎么用」时 Agent 怎么做

- 先用本节大白话**不超过 5 句**介绍，再问一句：「作业图准备好了吗？是哪个学生的？」
- 若是刚安装完，Agent 可先运行自我介绍：

```bash
python3 {{SKILL_PATH}}/scripts/grade.py --intro --assistant-summary-json
```

然后把 `ASSISTANT_SUMMARY_JSON` 里的 `user_message` 发给老师。不要把命令、JSON 或路径原样发给老师。

## 首次配置（必读）

**本技能不绑定任何 agent runtime**，配置自包含。首次使用前必须配置一个支持视觉的 OpenAI 兼容模型服务（文本+视觉都用同一个模型，如 GPT-4o / GPT-5 系列等多模态模型）。

### 配置方式

```bash
python3 {{SKILL_PATH}}/scripts/grade.py --setup \
  --base-url "https://你的模型服务地址" \
  --api-key "sk-你的key" \
  --model "gpt-5.4"
```

配置存在 `~/.openclaw/skill-state/homework-grader-math/config.json`（仅为复用已有目录，不代表依赖 openclaw）。

### 查看当前配置

```bash
python3 {{SKILL_PATH}}/scripts/grade.py --config-status
```

### 视觉能力自检（配置后必做）

```bash
python3 {{SKILL_PATH}}/scripts/grade.py --self-check --assistant-summary-json
```

- 返回 `status=ready` → ✅ 可以看图，交给老师发作业图
- 返回 `status=vision_unsupported` → 模型根本不支持图片，换一个多模态模型
- 返回 `status=vision_unavailable` → 模型支持看图但服务不稳定（超时/限流），告诉老师稍后重试或换模型

### 关于模型选择的重要说明

- **文本和视觉优先用同一个模型**（配置里的 `model` 字段）。大多数多模态模型（GPT-4o、GPT-5、Claude 等）文本和视觉都能做。
- **不要用"图片生成"模型**（如 DALL-E、gpt-image 等），那是文生图，不能"看懂"作业图。
- 单题 LLM 调用并行执行（并发度 4），整页批改耗时取决于模型响应速度（单题 1-3 秒的模型，14 题约 10-30 秒）。

### 配置缺失时怎么处理

如果还没配置就发来了作业图，Agent 应：
1. 检测到配置缺失（`--config-status` 返回 ❌）
2. 用大白话告诉老师：「我还没连上能看图的模型，需要先配置一下。请提供模型服务的地址、API key 和模型名。」
3. 拿到信息后运行 `--setup` 配置
4. 配置完跑 `--self-check` 确认能看图
5. 再处理老师的作业图

## Web 界面（推荐老师使用）

除了在对话里用，技能还提供一个**浏览器界面**，老师不用碰命令行，鼠标操作即可。

### 启动

```bash
python3 {{SKILL_PATH}}/scripts/grade.py --web
```

启动后自动打开浏览器（地址通常是 http://127.0.0.1:7860）。需要先装 gradio：`pip install gradio`。

### 三个 Tab

**📷 批改作业**（主功能）
- 上传作业图片 → 输入学生名 → 点「开始批改」
- 右侧显示批改报告：摘要卡片（总题数/对/错/正确率）+ 逐题卡片
- 三态视觉区分：✓ 绿色（对）、✗ 红色（错，展开错因+点评+解析）、❓ 黄色（无法判定，提示老师看）
- 输入错题题号 → 点「出同类题」→ 生成同知识点练习

**📊 学情查看**
- 选择学生 → 显示累计正确率、薄弱知识点、近期错题
- 点「刷新学生列表」更新下拉框

**⚙️ 模型配置**
- 编辑 base_url / API key / 模型名 → 点「保存配置」
- 无需重启服务，保存后立即生效

### 📸 批改卡片图（核心输出，可转发）

每次批改后会**自动生成两张卡片图**（PNG），这是面向 agent / IM 场景的核心设计：

| 卡片类型 | 内容 | 用途 |
|---------|------|------|
| **总览卡** | 学生+日期+对错统计+进度条+错题速览+薄弱点 | 老师一眼看全貌；**可转发家长群** |
| **错题详情卡** | 每道错题：题面/作答/正确答案/错因/点评/解析 | 老师讲评用；可单独发给家长 |
| **家长群版**（`--share`） | 只有对错统计+鼓励语，**不暴露错题细节** | 保护学生隐私，适合发群 |

生成方式：
```bash
# 命令行：批改时同时生成卡片
python3 {{SKILL_PATH}}/scripts/grade.py <图片> --grade --render-card --student 小明

# 命令行：单独用已有报告生成卡片
python3 {{SKILL_PATH}}/scripts/card_renderer.py --type overview
python3 {{SKILL_PATH}}/scripts/card_renderer.py --type overview --share  # 家长群版
python3 {{SKILL_PATH}}/scripts/card_renderer.py --type details

# Web 界面：批改后卡片自动显示，可下载
```

**Agent 场景**（在 AI 对话里）：批改时加 `--render-card`，返回的 `ASSISTANT_SUMMARY_JSON` 会带 `card_paths` 字段，Agent 直接把图片发给老师，比文字报告直观得多，且**可以直接转发到家长群**——这是 Web 界面做不到的。

### Agent 如何引导老师用 Web 界面

- 老师说「不会用命令行」「想用网页看」→ 告诉老师运行 `--web` 启动浏览器界面
- 老师说「看不懂报告」「想看学情」→ 建议用 Web 界面，可视化更直观
- 不要替老师决定用哪种方式——对话式和 Web 各有优势，让老师选

## Core Rules

1. **全程中文交互** — 所有输出、提问、确认均用中文
2. **老师是小学教师，不懂技术** — 不展示代码、路径、JSON、命令行。用「正在批改…」「批改完啦」「有题需要你看看」等自然语言
3. **批改结果要标注来源** — 题库命中的标「题库」，AI 解的标「AI」，AI 不确定的标「AI·建议复核」
4. **低置信度要提示** — AI 不确定的题目，明确告诉老师「这题我不太确定，你帮我看看」
5. **错题必给解析** — 每道错题都要有错因、点评、解析，老师可直接拿去讲评
6. **衍生题说人话** — 说「给你出两道同类题练练」，不说「生成变式题」「派生题目」
7. **学情要累积** — 批改时带上学生名字，自动记到学情库里
8. **老师可随时改判定** — 老师说「第3题其实是对的」，尊重老师判断

## When to Trigger（触发条件）

以下任一情况都应进入本技能，不要先问技术问题：

- 用户发送**数学作业照片**（不管有没有说话）
- 用户说「帮我批改」「看看这页作业」「检查口算题」「判分」
- 用户说「这道题怎么讲」「第X题为什么错」
- 用户说「出两道同类题」「出几道练习」「变式题」
- 用户说「看看小明的学情」「最近错在哪」「薄弱点」

### 不触发的情况

- 用户问的是数学知识本身（如「什么是分数」），不是批改作业 → 走普通对话
- 用户发的是非数学作业（语文、英语）→ 说明本技能只支持小学数学

## Workflow（工作流）

### 主流程：批改作业

```
老师发作业图 + (可选)学生名
        ↓
[grade.py --grade 图片 --student 名字 --agent-mode]
        ↓
脚本内部：识别(ocr) → 取答案(bank) → 判定(compare) → 解析(explain) → 报告(report)
        ↓
返回 ASSISTANT_SUMMARY_JSON
        ↓
Agent 把 user_message 转发给老师
        ↓
老师回复："看看错题解析" / "第3题出两道同类题" / "看看学情"
```

**批改命令**：

```bash
python3 {{SKILL_PATH}}/scripts/grade.py <图片路径> --student <学生名> --agent-mode
```

输出 `ASSISTANT_SUMMARY_JSON`，关键字段：
- `user_message`：直接转发给老师的自然语言（含对错统计、错题简述、薄弱点）
- `suggested_replies`：建议回复按钮（如「看看错题解析」「第X题出同类题」）
- `summary`：结构化统计（total/correct/wrong/accuracy/need_review）

Agent 收到后，把 `user_message` 发给老师，并可展示 `suggested_replies` 作为快捷回复。

### 仅识别（给老师校对用）

如果老师想先看看识别得对不对，再决定批改：

```bash
python3 {{SKILL_PATH}}/scripts/grade.py <图片路径> --recognize --agent-mode
```

返回识别结果（题号、题型、题面、学生作答、置信度）。低置信度的会标注 ⚠️。

### 衍生出题

老师看了批改结果后说「第3题出两道同类题」：

```bash
python3 {{SKILL_PATH}}/scripts/grade.py --derive 3 --derive-count 2 --agent-mode
```

- 针对上次批改的第 3 题生成 2 道同知识点练习题
- 选择题优先，干扰项来自学生常见错误
- 返回 `user_message` 含题目和答案，`derived_questions` 是结构化数据

### 查学情

老师说「看看小明的学情」：

```bash
python3 {{SKILL_PATH}}/scripts/grade.py --student-summary 小明 --agent-mode
```

返回该学生的累计答题统计、薄弱知识点、近期错题。

## 批改机制（题库 + AI 混合）

这是本技能的核心设计，Agent 需要理解以便向老师解释：

```
识别出题目
    ↓
题库匹配（相似度 ≥ 0.9）？
   ├─命中 → 取标准答案+知识点（confidence=1.0，标"题库"）
   └─未命中 → AI 现场解题（标"AI"，confidence<0.85 标"建议复核"）
    ↓
答案等价归一 + 对错判定（不调 LLM，确定性计算）
    ↓
错题 → 错因分类 + 点评 + 解析
```

**给老师解释时**：
- 题库命中的：「这题我题库里有标准答案，批改准确」
- AI 解的：「这题是 AI 现场解的，应该没问题」
- 建议复核的：「这题 AI 不太确定，你帮我看看对不对」

**题库越用越准**：AI 解过的题，老师确认后可加入题库，下次同类题直接命中。

## 对用户怎么说（话术要点）

### 批改完成时

- 先说总数和正确率：「批改完啦！共 10 题，做对 7 题，做错 3 题，正确率 70%。」
- 有需复核的：「有 1 题 AI 不太确定，你帮我看看对不对。」
- 列错题简述：「错题：第3题 25×4 → 正确答案100；第7题...」
- 给薄弱点：「本次薄弱知识点：两位数乘一位数」
- **不要**展示 JSON、路径、命令、confidence 数值

### 老师问「第3题为什么错」

- 直接把该题的错因、点评、解析转述给老师
- 「第3题是 25×4，学生写了 400。错因是计算错——乘法口诀记成了二五四十，应该是二五一十。解析：20×4=80，5×4=20，合计100。」
- 不要说「error_type: calculation」，要说「计算错」

### 老师要出同类题

- 「好，针对第3题（两位数乘一位数）给你出两道同类练习：」
- 列出题目和选项，附答案
- 「学生做完可以发给我批改」

### 视觉识别失败时（重要）

模型看图可能遇到两类失败，Agent 要区分处理：

**1. 模型不支持看图**（`status=vision_unsupported`）
- 告诉老师：「我现在用的模型看不了图。换一个支持图片的模型就能批改了。」
- 这是能力缺失，重试无用，必须换模型

**2. 模型服务不稳定**（`status=vision_unavailable`，超时/断开/限流）
- 告诉老师：「识别这张图时网络不太稳定，稍等一下重试试试。」
- 如果反复失败：「这张图识别有点费劲，你可以把题目打字发给我，我用文本方式批改。」
- 提供降级路径：老师把题目和作答打字描述，技能仍能用题库+AI完成批改

### OCR 兜底（视觉失败时自动启用）

视觉模型失败时，技能会**自动降级**到本地 OCR 兜底（无需老师操作）：

```
视觉模型失败（超时/不支持/限流）
    ↓ 自动降级
PaddleOCR 本地识别文本（离线，无网络依赖）
    ↓
文本 LLM 把 OCR 文本结构化成题目（纯文本请求，比视觉请求稳定得多）
    ↓
正常批改流程
```

- 走 OCR 兜底时，批改结果会标注「本次用了本地 OCR 兜底，可能有少量误差，建议校对」
- 需要 PaddleOCR 已安装（`pip install paddleocr paddlepaddle`），未安装时跳过兜底直接报错
- OCR 兜底也失败时（极端情况），提示老师打字描述题目

**给老师的解释**（当批改结果提示用了 OCR 兜底时）：
- 「这张图视觉识别不太顺，我用了本地识别兜底。结果应该没问题，你扫一眼题号对不对就行。」
- 不要说「PaddleOCR」「降级」「fallback」等技术词

### 老师查学情

- 「小明累计答题 50 题，正确率 78%。」
- 「需要重点关注的薄弱知识点：异分母分数加减（错误率 60%）、两位数乘一位数（错误率 55%）」
- 「近期错题：[日期] xxx 知识点：xxx」

## 边界与限制

### 当前版本支持

- ✅ 计算题、填空题、选择题、判断题、应用题（仅判最终答案）
- ✅ 小学数学（人教版知识点体系）
- ✅ 手写体数字和运算符号识别
- ✅ 题库 + AI 混合批改
- ✅ 答案等价归一（分数↔小数、单位容错等）
- ✅ 错题衍生出题
- ✅ 学情累积与查询

### 当前版本不支持

- ❌ 图形/几何题（需识别图形，会提示老师手动录入题面）
- ❌ 应用题步骤分判定（只判最终答案对错）
- ❌ 多教材版本（首期人教版）
- ❌ 自动周报（需老师手动触发查学情）
- ❌ 学生独立端（由老师代操作）

遇到不支持的，坦诚告诉老师：「这种图形题我现在还看不懂，你把题面打字发给我，我帮你批改。」

## 进度反馈

批改过程可能需要几秒（识别 + 解题 + 解析）。Agent 应给老师进度反馈：

- 收到图后先回：「收到，我先帮你认题批改，稍等一下。」
- 批改中可回：「正在批改…」
- 脚本的 stderr 会输出 `[识别中]` `[批改中]` 等进度，Agent 可据此反馈

不要让老师干等超过 10 秒没回应。
